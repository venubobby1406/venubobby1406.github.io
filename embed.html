02 — Every knob

Everything is set with attributes on the script tag. If you prefer an object, set window.ClipSolo = { … } before the script loads.

AttributeDefaultWhat it does
data-endpoint—Where the finished clip is POSTed (multipart: file, width, height, duration). Leave it out and the visitor simply downloads the file.
data-labelRecordThe label shown on the button in your page.
data-accent#E23B2EThe accent colour of the recorder UI — the red is the REC colour, the rest follows your accent.
data-cameraonSet to off to hide the camera bubble entirely.
data-frameonSet to off to drop the studio frame and record the raw screen.
data-pad48Frame padding in pixels (0–120).
data-radius24Frame corner radius in pixels (0–48).
data-bg#1B1D22Frame background colour.
data-max900Longest clip in seconds before it stops itself.

The studio frame is baked into the clip as it records. Cap can frame a take too — but theirs is a desktop app someone installs, and this is one script tag on your own site.

The camera, the microphone and the frame are also switches inside the recorder — your visitor decides for their own take, and their choice is never sent anywhere.

05 — What it does not do yet

The honest list. If something here matters to you, tell us and we will build it — we would rather you knew first.

No trimming inside the embedThe main app trims before you export. The embed records and hands over the file as it is.
WebM outputVP9 or VP8, the format the browser encodes natively. Convert it to MP4 in your pipeline — or with our local converter.
No share linksA share link needs a server holding the file. That is the one thing we do not do by default — you host it, or nobody hosts it.
No team workspacesThere are no seats, no permissions and no dashboard. The embed is a recorder and a POST, nothing else.
No transcriptSpeech-to-text is a server job. Your endpoint can do it — the clip arrives as a normal file.
Not on iOS SafarigetDisplayMedia is not available there. The recorder will tell the visitor plainly instead of failing silently.

07 — Straight answers

If something here is wrong, tell us and we will fix the page and this list at the same time.

Does anything about the recording reach ClipSolo?

No. There is no upload endpoint on our side and no account to create. The file is encoded in the visitor’s browser and goes where you tell it to go. If you self-host the script, there is not even a request to our domain.

What does my endpoint receive?

A multipart/form-data POST with the clip as file (a WebM blob), plus width, height and duration. That is the whole contract — there is no SDK to install on your server.

Does my user need to install anything?

No. It is a web page. They click your button, choose what to share, and record. The only browser requirement is screen capture support, which in practice means Chrome or Edge.

Can I put it behind my own login?

Yes, and you should. The embed only opens the recorder — whatever you do with the file is your logic. Add your own session check before you render the button if it matters.

Does it work on mobile?

Phones have no screen to share, so there is nothing to record. The embed is for desktop browsers; the file tools on this site work on mobile.

Is this the same code as the recorder on this site?

The same ideas and the same look, written to be a single self-contained file with no dependency on the rest of the site. The bench here has more in it; the embed has exactly what an embed needs.
